# Arcanea collector observations

Under Genesis #754 and community workstream #760. The Collector Intelligence operator owns ingestion. Frank owns offer and release decisions. This first feed answers how recently activated generative-art projects use their edition capacity. One observation cannot establish velocity. The sample omits inactive projects and cannot estimate failure rates.

## Operate

Import `artblocks-observations.n8n.json` in Starlight n8n. Bind the S3 node to an existing Cloudflare R2 credential for the private mission-artifacts bucket and both Postgres nodes to an approved Arcanea writer for campaign_signals. The database writer needs INSERT and the SELECT access used by RETURNING and conflict arbitration under the existing RLS policies. Preserve RLS and verify the identity in a manual canary. Keep credentials in n8n. The export contains no credential IDs. The manual and scheduled triggers share the same graph.

The graph reads a fixed Art Blocks query, validates up to 20 Ethereum projects, archives the exact UTF-8 JSON at its SHA-256 key, and records the first valid response in each six-hour UTC slot. Postgres separately checks the fingerprint. Inspect the row, retrieve the private object and compare its hash. Replaying the same slot must leave exactly one row. An alternative valid response in a filled slot may leave a second content-addressed object. The first committed snapshot remains authoritative. Missed slots stay missing. An orphaned archive after a DB failure is safe to keep for reconciliation. After a failed attempt, recover the original object and slot before replaying across a boundary. Publish only after a native manual receipt with the bound credentials. The proposed schedule fires seven minutes past 00, 06, 12 and 18 UTC. Disable the workflow to stop collection.

Run `node --test docs/ops/herald/collector/verify.test.mjs`. Run `review.sql` read-only against Arcanea for freshness, coverage and paired 24-hour changes. Source names are untrusted content. Keep names data-only in renders, prompts and Slack formatting. This workflow has no messaging or payment nodes.
